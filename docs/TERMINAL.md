# Terminal window (v1.13.0)

RioOS has no GUI any more. The only thing shown in the QEMU window is the
shell, drawn by the kernel as a text terminal on the Bochs/QEMU VBE linear framebuffer (`-vga std`).

| Script | What you get |
|---|---|
| `run.sh` / `run.ps1` | RioOS in the host terminal (QEMU `-nographic`, serial console). |
| `run-terminal.sh` / `run-terminal.ps1` | RioOS in a QEMU window: black background, light-grey text, DejaVu Sans Mono font. The serial console stays attached to the host terminal for boot messages. |

## How it works

- `drivers/fb.cpp` finds the QEMU VGA device over PCI, programs the Bochs VBE registers for 1024x768x32 and exposes the linear framebuffer.
- `drivers/console.cpp` is the terminal: a ring of 2000 text lines (the scrollback), a VT100/ANSI parser (cursor movement, erase line/screen, insert/delete, SGR colours, `ESC[?25h/l`), and a lazy renderer that repaints only the cells that changed.
- Every byte printed with `uart_putc()` is mirrored to the console once it is active, so the window shows exactly what the serial shell shows, including `nano`, `calc` and any ring 3 program. Without a display (`run.sh`) nothing changes: the console simply never starts.
- Font: DejaVu Sans Mono rendered with anti-aliasing at a 9x18 cell (`drivers/console_font.cpp`, generated by `tools/gen_console_font.py`; see `THIRD_PARTY_NOTICES.md`). Palette: the Linux virtual-console colours (what an Arch Linux tty uses). The prompt is drawn Arch-style: green `[user@RioOS`, blue directory, red `#` for root.
- Window size: 112 columns x 42 rows.

## Scrolling

| Input | Action |
|---|---|
| Mouse wheel up / down | Scroll 3 lines through history |
| Shift+PageUp / Shift+PageDown (or PageUp / PageDown) | Scroll one page |
| Any key, or new output | Jump back to the live screen |

A thin scroll bar appears on the right edge while you are looking at history.
The mouse is a PS/2 IntelliMouse (relative), so QEMU only sends wheel events
while the window has grabbed the pointer. `run-terminal.sh` starts the GTK
window with `grab-on-hover=on`, so simply moving the pointer over the window is
enough (release with Ctrl+Alt+G). PageUp/PageDown always work.

## Input

Keyboard input comes from the PS/2 keyboard (scancode set 1, polled). Up/Down
arrows browse command history in the window the same way ESC `[A`/`[B` do on
the serial console; Tab completion and `Backspace` work in both. Serial (COM1)
input stays available.

## Tests

`tests/console_host_test.cpp` renders into an in-memory framebuffer and checks
geometry, text/cursor handling, LF/CR behaviour, erase and cursor addressing,
SGR colours, wrap, scrollback accumulation, wheel/page scrolling and clamping,
snap-to-bottom, exact restoration of the live frame, anti-aliasing, and
robustness against hostile escape sequences.
`RIOOS_CONSOLE_SNAPSHOT=out.ppm` makes the test also write a screenshot.

Not covered by host tests: real QEMU VBE/PS/2 behaviour. Test that on a machine
with `qemu-system-x86_64` (`bash linux/run-terminal.sh`). The build was also
exercised on a purpose-written x86-64 emulator (boot, shell, nano, calc,
PageUp/PageDown and IntelliMouse wheel scrolling).
